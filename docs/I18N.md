# Interface languages

EditMdView includes Simplified Chinese and English UI language files. The **语言 / Language** button on the main toolbar changes the language immediately. The selected value is remembered for the current Windows user.

## Selection order

1. `EDITMDVIEW_LANGUAGE` environment variable, intended for testing or managed deployments.
2. `%LOCALAPPDATA%\EditMdView\language.ini`, created automatically on first run and updated by the toolbar language menu.
3. A legacy `language.ini` beside `EditMdView.wlx` or `EditMdView.wlx64`, used only to seed or recover the per-user setting.
4. `auto`, which follows the Windows user interface locale.

The generated setting accepts `auto`, `zh-CN`, `en-US`, or the file name of another catalog in `lang` without the `.lng` extension.

```ini
language=auto
```

## Adding a language

Copy `lang\en-US.lng` to a locale-named file such as `lang\de-DE.lng`, translate the values after `=`, and keep the English source text before `=` unchanged. Save the file as UTF-8. The new locale is discovered automatically and appears in the toolbar menu.

```ini
# Comments begin with # or ;
Save=保存
The file was modified by another program.=当前文件已被其他程序修改。
```

Supported escapes in values are `\n`, `\r`, `\t`, `\\`, and `\=`. Missing entries safely fall back to the original English source string. `Ctrl+Shift+R` reloads the active language catalog together with the editor configuration.

The preference is stored outside the plugin directory so language switching still works when Total Commander is installed under a protected folder. The release package does not contain `language.ini`; delete `%LOCALAPPDATA%\EditMdView\language.ini` to let EditMdView recreate it with `language=auto` on the next run. An old plugin-root file remains readable for backward compatibility and is migrated into the per-user setting when possible.
